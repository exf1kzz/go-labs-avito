# Trip Service

HTTP-сервис управления поездками.

Сервис позволяет:

- создать поездку;
- получить поездку по идентификатору;
- завершить активную поездку;
- проверить состояние сервиса и доступность PostgreSQL.

## Требования

Для запуска необходимы:

- Go 1.24 или новее;
- Docker;
- `tripgoctl`;
- `make`.

Проверить окружение командой:

```bash
tripgoctl doctor
```

## Запуск

### 1. Запуск кластера

Кластер достаточно запустить один раз на машине:

```bash
tripgoctl cluster start
```

При следующих запусках повторять эту команду не требуется.

### 2. Запуск окружения

```bash
make start
```

Команда поднимает PostgreSQL и создаёт файл `.env` с реальным адресом базы данных.

Проверить состояние окружения:

```bash
make status
```

Посмотреть параметры подключения:

```bash
make connect
```

Файл `.env.example` содержит полный список переменных и значения по умолчанию.  
При запуске сначала загружается `.env.example`, затем `.env`, поэтому адреса,
созданные `tripgoctl`, имеют приоритет.

Копировать `.env.example` поверх созданного `.env` не нужно.

### 3. Применение миграций

```bash
make migrate
```

Команда создаёт таблицы, ограничения и индексы PostgreSQL.

Проверить состояние миграций:

```bash
make migrate-status
```

Откатить последнюю миграцию:

```bash
make migrate-down
```

Откатить все миграции:

```bash
make migrate-down-all
```

### 4. Запуск сервиса

```bash
make run
```

По умолчанию сервис доступен по адресу:

```text
http://localhost:8080
```

Проверить работу процесса:

```bash
curl -i http://localhost:8080/health
```

Проверить готовность сервиса и соединение с PostgreSQL:

```bash
curl -i http://localhost:8080/ready
```

Обе ручки должны вернуть `200 OK`.

### 5. Остановка окружения

```bash
make stop
```

## Остальные команды Makefile

Сгенерировать Go-код из OpenAPI-контракта:

```bash
make generate
```

Запустить тесты с детектором гонок:

```bash
make test
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `HTTP_ADDR` | Адрес HTTP-сервера |
| `HTTP_READ_TIMEOUT` | Таймаут чтения запроса |
| `HTTP_READ_HEADER_TIMEOUT` | Таймаут чтения заголовков |
| `HTTP_WRITE_TIMEOUT` | Таймаут записи ответа |
| `HTTP_IDLE_TIMEOUT` | Таймаут неактивного соединения |
| `LOG_LEVEL` | Уровень логирования |
| `SHUTDOWN_TIMEOUT` | Таймаут graceful shutdown |
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `DATABASE_MAX_CONNS` | Максимальное число соединений |
| `DATABASE_MIN_CONNS` | Минимальное число соединений |
| `DATABASE_MAX_CONN_LIFETIME` | Максимальное время жизни соединения |
| `DATABASE_CONNECT_TIMEOUT` | Таймаут подключения к БД |
| `DATABASE_QUERY_TIMEOUT` | Таймаут выполнения запроса |

Пример значений находится в `.env.example`. Файл `.env` создаётся окружением.

## Решения

### Уровень изоляции транзакций

Используется `READ COMMITTED`. Для операций сервиса его достаточно, потому что конкурентное завершение поездки контролируется
атомарным условным `UPDATE`, а создание второй активной поездки запрещается ограничением на уровне базы данных.

### Менеджер транзакций

Менеджер транзакций начинает транзакцию через `pgxpool`, сохраняет `pgx.Tx` в `context.Context` и передаёт этот контекст в вызываемую функцию.
Репозитории получают из контекста либо текущую транзакцию, либо пул соединений.

При успешном выполнении производится `COMMIT`, при ошибке — `ROLLBACK`. При панике транзакция также откатывается,
после чего паника передаётся дальше. Вложенный вызов использует уже открытую транзакцию.

### Запрет двух активных поездок

На уровне PostgreSQL создан частичный уникальный индекс по `driver_id` только для строк со статусом `active`.

За счёт этого PostgreSQL не позволяет создать две активные поездки для одного водителя даже при одновременных конкурентных запросах.

При нарушении индекса PostgreSQL возвращает ошибку `23505`. Репозиторий проверяет код ошибки
и имя ограничения, после чего преобразует её в доменную ошибку `driver busy`.

После завершения поездки её статус перестаёт быть `active`, поэтому для этого водителя можно создать новую поездку.
